# Repository agent instructions

1. Read HANDOFF.md before making project changes. It is the canonical cross-chat project state.
2. Keep HANDOFF.md current. After every committed code, UI, behavior, branding, configuration, deployment, or workflow update, update HANDOFF.md in the same work session.
3. Record accepted/current state only. Clearly label experiments, rejected directions, and unresolved work.
4. The canonical branch is main unless the user explicitly requests another branch.
5. Do not restore discarded branding/logo directions merely because old files remain in the repository.
6. When GitHub write access is available and the user asks for a repository change, apply it directly rather than only describing manual steps.
7. Fetch a fresh file SHA before editing an existing GitHub file.
